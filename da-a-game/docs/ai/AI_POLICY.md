## 0. 总原则

1. **合法性由引擎裁决**（`canBeat` / `canCapture`）。AI 不自判牌型，只在合法候选集里挑。
2. **阵营只按公开信息 + 可推定信息**判断，绝不用引擎的真阵营表（暗打时）。
3. **固定排序键**：候选集按 `SORT_KEYS` 排完取第一个。

## 1. 阵营可见性（敌/友/不明）—— 唯一来源 `src/camp.js`

`campOf(state, viewerId, targetId)` → `SELF` / `ALLY`（友） / `ENEMY`（敌） / `UNKNOWN`（不明）。

| 状态 | 含义 | 依据 | AI 行为 |
|---|---|---|---|
| SELF | 自己 | —— | —— |
| ALLY 友 | 队友(已知) | 同阵营表 / 我是次方时的主A / 我是主A时的次方 / **推定次方后的其余未知玩家** | 不用重手压他；不取他的牌 |
| ENEMY 敌 | 敌人(已知) | 同阵营表 / 主A持有者 / **推定出来的次方** | 可以出任何牌压制他 |
| UNKNOWN 不明 | 可能是队友也可能是次方 | 次方未亮明且还没有推定线索 | 普通牌可压；**蛋子+ 不压** |

判定顺序（代码 `src/camp.js` 的 `campOf`）：

1. 公开（次方亮明 / 明打）→ 用真阵营表
2. 我就是次方 → 主A持有者是**友**，其余是**敌**
3. 我是主A持有者 → **暗打时他也不知道谁是次方**（其他人一律**不明**）；推定出次方后 → 那个次方是**友**（主方两口子），其余是**敌**
4. 我是抓方 → 主A持有者是**敌**；若从公开出牌流水**推定**出次方 → 他是**敌**，**其余未知玩家都是友**（裁定 A）；
   还没有推定线索 → 其余一律 **UNKNOWN**

> 敌友钮（头像旁的三态 ?/友/敌）用同一份判定：公开确定阵营最优先，其次**手动标记优先**，没手动标就自动填（`ui-render.js`）。
> AI 的出牌决策读的就是这份标记（`src/ai.js` 的 `_isSameCamp` / `_campUncertain` 都走 `src/camp.js`）。

## 2. 候选生成与过滤

### 2.1 合法性（引擎）
候选组合必须 `canBeat` 过桌面；`[4]取牌` 走 `canCapture`。

### 2.2 硬性过滤（不合法就不进候选）

- 双大A：两张同花色主A 要么一起出、要么都不出（不与别的牌混出）。
- 双王：两个王一起出或都不出（不拆开出单王）。
- 三王：可拆成一个王单出，剩余两个王一起出。也可三个王一起出。
- 四王：拆成两个双王出。

> 王的拆法只看**这一手用了几张王**：2 张王只能一起出或都不出；3 张王可用 1 / 3 张；4 张王可用 2 / 4 张。

> **大A 进龙不是硬过滤**：单张大A **允许**进龙；「优先普通A进龙」是**排序**口径（`power` +500 → 靠后），不是合法性口径。

### 2.3 阵营过滤

- 同阵营（公开或已知）：不用 王 / 大A / **蛋子及以上** 去压，不用4取牌。
  - **例外**：这一手能把**手牌打完**（出完优先）时**放行** —— 同阵营也压（`src/ai.js` 的 `_willEmpty`）。
- **不明**（次方未亮明）：不用 **蛋子+** 去压 —— 那人可能是队友，浪费重手；不用三个及以上的4取牌。

> 取牌的阵营过滤在 `src/ai.js` 的 `_capCampOk`（用 `src/camp.js` 的 `campOf` 取关系）。
- **推定为次方**：阵营已知（敌人）→ 不受此限，本局可以出任何牌压制他。

### 2.4 「X+」= X 及以上（用户 2026-11-07 22:26 裁定 B）

- **蛋子+ = 蛋子及以上**（12 型）：蛋子 / 大蛋子 / 双王 / 连珠蛋 / 假八 / 真七 / 真八 / 三王 / 大连珠蛋 / 大假八 / 四王 / 双大A
- **大蛋子+ = 大蛋子及以上**（11 型）：上面去掉「蛋子」
- **双龙不属于蛋子+**（用户 22:48 补充）：双龙是**独立牌型**（SKILL §6.4 单独处理），既不在蛋子+，也不在大蛋子+。

## 3. 排序键（唯一有序表 · `src/ai-policy.js` 的 `SORT_KEYS`）

| 序 | 键 | 含义 | 为什么在这个位置 |
|---|---|---|---|
| 1 | `outAll` | 出完优先 | 能一次走完就走完；**假八/大假八同样适用，没有例外** |
| 2 | `splitEgg` | 组合牌型拆了 ≥2 个同点组 | QQKKKKA 不能出 QKA（动了 QQ+KKKKK）；QKKKKA 可以（只动 KKKKK）。**同点数家族拆同点组是硬过滤**，见 3.1 |
| 3 | `sameType` | 同牌型优先 | 上家出 JJ、手牌 22777 → 选 22 不选 777 |
| 4 | `power` | 牌力等级（§6.3 链），弱牌先出 | 双王 < 假八 < 真七；**含大A 的牌 +500 → 最后** |
| 5 | `fourEgg` | 4 组成的蛋子+ 靠后 | 有别的选择就别出 4 组成的蛋子+ |
| 6 | `split` | 不拆同点组 | 拆开的 999 不该赢整组 9999 |
| 7 | `bigGroup` | 大组牌型靠后 | 大组是最后手段，但排在「不拆组」之后 |
| 8 | `kv` | 保留价值低优先 | 打出留着的价值低的牌 |
| 9 | `len` | 张数少 | 同上，收尾用 |

> 裁定 E：**不拆组 > 同类型优先**（`splitEgg` 在 `sameType` 之前）。
> 顺序由 `tests/test-ai-policy.js` 锁住 —— 改顺序必须同时改那条测试（有意摩擦）。


### 3.1 同点数的牌不拆（硬过滤）

- 同点数家族（对子/蛋子/大蛋子/真七/真八）的候选，只要**拆了**手里的同点组 → **不进候选**（硬过滤，不是降权）。
  例：手里 333、桌面 22 → 不许出 33，只能出 333 整组或过牌；手里 22222 → 不许拆出 222。
- 单张拆组不罚（手里 66 出 6 仍正常，否则会出现没牌可出）。
- 为什么必须硬过滤：333 这类整组会被「阵营不明不用蛋子+」那条过滤掉；若拆组只降权，剩下的 33 仍是唯一候选 → 还是拆。
## 4. 起手 / 提示 / 托管 三者同源

起手选牌唯一来源 `src/lead-choice.js`；【提示】第一个候选 = `chooseAction` 的结果（即托管那一手）。三处共用，算法不漂移。

## 5. 取牌（4）

- 取 N 张目标用 N−1 张 4；4 组不足 3 张可整组用掉；4 组 ≥3 张不拆。
- 取牌优先度靠前；4 组成的蛋子+ 靠后；不取同阵营的蛋子。

**什么时候打**（2026-11-08 16:03 用户裁定：AI决策的log太多了，不用每次出牌都出）：

| 场景 | 打决策轨迹？ |
|---|---|
| AI 自己**出牌** | **不打**（只有 `AI 甲 PLAY (3张) ♠5` 这种摘要行） |
| AI 自己**过牌** | **不打** |
| 托管代打**出牌** | 打，且与牌名合成一行 |
| 托管代打**不出** | 打 |
| AI **手牌空**自动过牌 | 打 |

真实一行（托管代打压制，2026-11-11 实测）：

```
托管: AI 代打 丁 出牌 1 张 ♦6 |   [AI决策] 丁 | 桌: SINGLE(1张) | 阵营不明 | 选: SINGLE(1张) 6 | 候选: SINGLE(1张){出完1 拆蛋组0 同型0 牌力10 4蛋0 拆组1 大组0 价值70 张数1} … | 压制
```

- **桌**：桌面牌型与张数。
- **阵营**：三态（阵营不明 / 同阵营 / 推定次方=**玩家名**）—— 被限制时这里能看出原因。
- **选**：AI 实际出的那手。
- **候选**：合法候选集（**枚举顺序，最多列 3 个**；排序后的顺序看【提示】），每项括号里是该候选的排序键取值。
- **决定键**：选中的这手和**第二名**在哪个键上分胜负 —— 这就是「为什么选它」（两候选各键都相同时**不出现**这一段）。
- 末尾是动作类型（起手 / 压制 / 用4取牌 / 无合法行动）。

排序键标签（唯一来源 `src/ai-policy.js` 的 `SORT_KEY_LABELS`）：**出完 / 拆蛋组 / 同型 / 牌力 / 4蛋 / 拆组 / 大组 / 价值 / 张数**。

## 7. 报障对照清单（目视看到不对时按这个顺序查）

先记三样：**桌面是什么牌型**、**他的手牌（点数+张数）**、**谁出的**；再看 `[AI决策]` 那行。

1. **他出的这手合法吗？** → 引擎 `canBeat` 说了算；不合法是引擎 bug。
2. **他拆组了吗？** → 看候选里的「拆蛋组/拆组」。
3. **他换牌型了吗？** → 看「同型」；同类型被拆组时由 `splitEgg` 顶掉。
4. **他浪费重手了吗？** → 看「牌力/大组/4蛋」。
5. **他为什么不出 X？** → X 被阵营过滤挡了（2.3），或 X 在排序里靠后。
6. **他压错人了吗？** → 看阵营三态，特别注意「推定次方」有没有触发。

## 10. 真人点选 vs AI 出牌（两条线）

- **AI 的口径只管 AI 自己**: 排序键(`SORT_KEYS`)、拆组罚则、阵营保守 —— 都不作用于真人。
- **真人点选的候选池 = 全量引擎合法组合**(`uiHintCandidates`): 只有引擎的合法性(能不能出), 没有拆组/优先度限制。
- 真人点一张牌后的自动补牌型顺序:
  1. 能跟已选的牌**整组出** -> 整组选上;
  2. 否则找**尽量保住已选牌**的合法组合(保住张数多的优先);
  3. 都没有 -> 点中的那张自己能出就不动, 否则按点中的那张补最小牌型。

> 例: 桌面 3456, 手里 999/88/7/6 —— 已选 678 再点 9 -> 选成 **6789**, 不被 999 顶掉。

## 13. 手动标记三态

- 循环顺序：**? → 友 → 敌 → ?**。
- 三态存 `friend` / `enemy` / `unknown`（不能用 `null`：`null` 表示「没标过」，会被自动判定覆盖 → 切不到问号）。
- 手动切成问号 = 明确表示「不明」→ AI 决策也按不明处理。

## 14. 取牌「取」标志

- 标志绑在「**那一手出牌**被取过」上，**不跟着牌走**。
- 有人被 4 取走 → 他座位前那手牌的**最后一张**右下角标「取」。
- 同一手牌以后再被打出 → 新的一手**没有**标志；只有重新被取才再出现。
- 实现：引擎出牌流水(plays)里 `kind='CAPTURE'` 的条目（其 `beat` = 被取走那手牌的主人）→ `uiTakenPlay[主人]=true`；渲染层只在**最后一张**右下角标「取」。**禁止**在牌对象上打标记（共享引用会误伤）。
