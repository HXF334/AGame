# 好友建房（联网对战）方案 · ONLINE_ROOM

> 状态：**方案已确认，P0 已完成**；开发在 `feature/online-room` 分支进行，验收后再合并 `main`。
> 本文是实施依据；规则口径仍以 `skills/da-a-game-rules/SKILL.md` 为准，决策以 `docs/DECISIONS.md` 为准。

## 1. 目标与边界

- 最多 5 个真人，按房间号组局；房主创建时可设：对局数（6/12/18/自定义，默认 12）、基础分（1/2/5/自定义，默认 1）、出牌时间（无托管/30s/60s/自定义 ≤99，默认无托管）、剩余牌数（显示/隐藏/自定义张数）、记牌器（默认关）、语音房（**暂不支持，置灰**）、空位 AI 补齐（房主可勾选，默认允许）。
- **基础分 × 每局得分累计**，全部对局结束后总结算。
- 联网只替换「驱动层」：`src/` 规则引擎原样复用，`game.js` 拆成 `localDriver` / `netDriver`。
- 不做：观战、回放、语音、跨房间匹配、排行榜（后续再说）。

## 2. 总体架构

```
客户端（小游戏）
  pages: 首页 / 创建房间 / 加入房间 / 对局
  net/       轮询 + 动作信封 + 重连
  driver/    本地引擎副本（只读渲染）+ 乐观提交
  src/       规则引擎（与单机同一份）
        ⇅  wx.cloud.callFunction
云函数 game-server（权威）
  engine/    由 tools/sync-engine.js 从 src/ 同步（MANIFEST.json 校验哈希）
  rooms/     校验、发牌、推进、视图裁剪、超时与 AI 补位
云数据库
  rooms      房间/座位/局数/配置/状态（权威 state 存这里）
  moves      每个动作的流水（seq、playerId、type、baseSeq）
  game_records  已有（单机战绩）
```

## 3. 一致性与防作弊

- **服务端权威**：所有 `transition` 在服务端执行；客户端只提交动作、渲染服务端下发的视图。
- **视图裁剪**：`src/public-view.js` 是唯一投影规则；别人的 hand 只给 `handCount`；`deck/dealOrder` 永不下发；`底牌公开 !== true` 时别人底牌为 null。
- **发牌在服务端**：`deal.js` 只在 `game-server` 内跑，客户端拿不到洗牌顺序。
- **版本/并发**：每次响应带 `seq`；客户端提交带 `baseSeq`；`baseSeq !== seq` 时服务端返回 `STALE`，客户端刷新视图后重试（不静默覆盖）。
- **幂等**：`protocol.actionKey()` 做同一动作重放去重。
- **记牌器**：只用公开流水 `plays`（服务端下发的视图里就有），不额外下发明牌信息。

## 4. 房间生命周期

- 创建：房主设置 → 生成 **6 位**房间号（不可与进行中房间重复）→ 写 `rooms`（status=WAITING）。
- 加入：按 6 位号加入；满 5 人（含 AI 补齐）自动开局；房主可踢未准备的人。
- 开局：服务端发牌 + 阶段闸门；真人超时按房间设置处理（无托管=不自动出，30/60s=超时自动 PASS，可配置）。
- 断线：座位保留 **90s**（`timing.RECONNECT`），期间轮询可恢复；超时后该座位交给 AI（托管标记），房主可继续。
- 退出：主动退出立即交给 AI；房主退出则转移给下一位真人。
- 局间：每局结束写 `game_records`（带 `roomId`），累计分；达到对局数后总结算面板。
- 兜底：懒判定（任何人读取房间时检查超时）+ 每分钟定时触发器扫一遍进行中房间。

## 5. 客户端页面

- 首页：单机 / 创建房间 / 加入房间 / 最近战绩。
- 创建房间：房间号（6 位，可改）、对局数、基础分、出牌时间、剩余牌数、记牌器、语音房（置灰）、空位 AI 补齐（勾选）。
- 加入房间：6 位输入 + 加入。
- 对局：复用现有牌桌 UI；顶部显示房间号/局数/累计分/轮询状态；断线时显示「重连中」。

## 7. 风险

- 云函数冷启动 + 1.5–2s 轮询 → 操作延迟可感知；先按用户确认的 1.5s 做，必要时改 WebSocket。
- 云开发单文档 1MB / 单次读写频率限制：state 需精简（不下发 deck/hand 给他人），动作流水单独集合。
- 棋牌类目与资质：个人主体+未认证目前只能体验版；上线前需确认。
- 并发写：同一房间的动作必须串行；用 `seq` 乐观锁 + 事务/条件更新，避免双写。
