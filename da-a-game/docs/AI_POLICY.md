## 0. 总原则

1. **合法性由引擎裁决**（`canBeat` / `canCapture`）。AI 不自判牌型，只在合法候选集里挑。
2. **阵营只按公开信息 + 可推定信息**判断，绝不用引擎的真阵营表（暗打时）。
3. **固定排序键**：候选集按 `SORT_KEYS` 排完取第一个。

## 1. 阵营可见性（三态）

| 状态 | 含义 | 依据 | AI 行为 |
|---|---|---|---|
| 公开 | 阵营确定 | 次方已亮明 / 明打 | 同阵营不压重手；非同阵营可压 |
| 推定 | 由行为推出 | 暗打 + 蛋子+ 线索（2.3） | 当敌人，本局可出任何牌压制他 |
| 不明 | 可能是队友，也可能是次方 | 次方未亮明 | 普通牌可压；**蛋子+ 不压** |

判定顺序（代码 `_campUncertain` / `_isSameCamp` / `_inferredNext`）：

1. 次方公开 或 **明打** → 公开
2. 我就是次方 / 我是主A持有者 → 我全知道（对方阵营明）
3. 对方被**推定**为次方 → 推定（敌人）
4. 否则 → 不明

> 2026-11-07 修过一个口径不一致：`_campUncertain` 以前没把「明打=身份公开」算进去，
> 导致明打下也误判「阵营不明」，AI 连普通蛋子都不敢出（回归 T9.2 抓到）。

## 2. 候选生成与过滤

### 2.1 合法性（引擎）
候选组合必须 `canBeat` 过桌面；`[4]取牌` 走 `canCapture`。

### 2.2 硬性过滤（不合法就不进候选）

- 双大A：两张同花色主A 要么一起出、要么都不出（不与别的牌混出）。
- 双王：两个王一起出或都不出（不拆开出单王）。
- 单张大A 不进龙（单张普通A 可以）。

### 2.3 阵营过滤

- 同阵营（公开或已知）：不用 王 / 大A / **蛋子及以上** 去压。
- **不明**（次方未亮明）：不用 **蛋子+** 去压 —— 那人可能是队友，浪费重手。
- **推定为次方**：阵营已知（敌人）→ 不受此限，本局可以出任何牌压制他。

### 2.4 「X+」= X 及以上（用户 2026-11-07 22:26 裁定 B）

- **蛋子+ = 蛋子及以上**（12 型）：蛋子 / 大蛋子 / 双王 / 连珠蛋 / 假八 / 真七 / 真八 / 三王 / 大连珠蛋 / 大假八 / 四王 / 双大A
- **大蛋子+ = 大蛋子及以上**（11 型）：上面去掉「蛋子」
- **双龙不属于蛋子+**（用户 22:48 补充）：双龙是**独立牌型**（SKILL §6.4 单独处理），
  既不在蛋子+，也不在大蛋子+。

## 3. 排序键（唯一有序表 · `src/ai-policy.js` 的 `SORT_KEYS`）

| 序 | 键 | 含义 | 为什么在这个位置 |
|---|---|---|---|
| 1 | `splitEgg` | 不拆蛋子级同点组 | 手上有 22222 就不该拆出 222 凑同牌型（D-028）。只罚 ≥3 张的组，拆对子出单张仍正常 |
| 2 | `sameType` | 同牌型优先 | 上家出 JJ、手牌 22777 → 选 22 不选 777 |
| 3 | `topType` | 双大A/双王/三王/四王/含大A **最后** | 不可替代的重手，留到最后 |
| 4 | `fourEgg` | 4 组成的蛋子+ 靠后 | 有别的选择就别出 4444（D-027） |
| 5 | `split` | 不拆同点组 | 拆开的 999 不该赢整组 9999（D-026） |
| 6 | `bigGroup` | 大组牌型靠后 | 大组是最后手段，但排在「不拆组」之后 |
| 7 | `kv` | 保留价值低优先 | 打出留着的价值低的牌 |
| 8 | `len` | 张数少 | 同上，收尾用 |

> 裁定 E：**不拆组 > 同类型优先**（`splitEgg` 在 `sameType` 之前）。
> 顺序由 `tests/test-ai-policy.js` 锁住 —— 改顺序必须同时改那条测试（有意摩擦）。

## 4. 起手 / 提示 / 托管 三者同源

起手选牌唯一来源 `src/lead-choice.js`；【提示】第一个候选 = `chooseAction` 的结果（即托管那一手）。三处共用，算法不漂移。

## 5. 取牌（4）

- 取 N 张目标用 N−1 张 4；4 组不足 3 张可整组用掉；4 组 ≥3 张不拆。
- 取牌优先度靠前；4 组成的蛋子+ 靠后；不取同阵营的蛋子。

## 6. AI 决策日志（裁定 C）—— 目视报障直接看这个

每手 AI 出牌后，`game.js` 打一行：

```
[AI决策] 戊 | 桌: BIG_TRIPLE(4张) | 阵营不明 | 选: BIG_TRIPLE(4张) 9,9,9,9 | 候选: BIG_TRIPLE(4张){拆蛋组0 同型1 重手0 4蛋0 拆组0 大组1 价值90 张数4} TRIPLE(3张){拆蛋组1 同型0 重手0 4蛋0 拆组1 大组0 价值90 张数3} | 决定键: 拆蛋组 | 压制
```

- **桌**：桌面牌型与张数。
- **阵营**：三态（阵营不明 / 同阵营 / 推定次方=X）—— 被限制时这里能看出原因。
- **选**：AI 实际出的那手。
- **候选**：合法候选集 + 每个候选的排序键取值。
- **决定键**：选中的这手和**第二名**在哪个键上分胜负 —— 这就是「为什么选它」。
- 末尾是动作类型（起手 / 压制 / 用4取牌 / 无合法行动）。

## 7. 报障对照清单（目视看到不对时按这个顺序查）

先记三样：**桌面是什么牌型**、**他的手牌（点数+张数）**、**谁出的**；再看 `[AI决策]` 那行。

1. **他出的这手合法吗？** → 引擎 `canBeat` 说了算；不合法是引擎 bug。
2. **他拆组了吗？** → 看候选里的「拆蛋组/拆组」。
3. **他换牌型了吗？** → 看「同型」；同类型被拆组时由 `splitEgg` 顶掉。
4. **他浪费重手了吗？** → 看「重手/大组/4蛋」。
5. **他为什么不出 X？** → X 被阵营过滤挡了（2.3），或 X 在排序里靠后。
6. **他压错人了吗？** → 看阵营三态，特别注意「推定次方」有没有触发。
