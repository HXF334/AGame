# 规则 ↔ 实现 三向对账

**规则唯一来源是 `skills/da-a-game-rules/SKILL.md`。** 本 Skill 只做**对账**，不改规则、不改引擎。

## 1. 为什么需要它

打大A 的规则落地分**三层**，三层各自独立演化，**历史上每次只改一层都出过 bug**：

| 层 | 文件 | 干什么 | 漏了会怎样 |
|---|---|---|---|
| **识别层** | `src/hand-types.js` | 判断这手牌**是不是**合法牌型、**能不能压过**桌面 | 规则判错 |
| **枚举层** | `src/combos.js` | 把手牌**拆成候选组合**交给识别层裁决 | 牌型合法但**枚举不出来** |
| **测试层** | `tests/` | 锁住行为 | 回归无人察觉 |

**识别层认得出 ≠ 枚举层枚举得到。** 枚举层漏一项，【提示】/ AI 选牌 / doPlay 组合回退**三条路径同时失效**——玩家看到「当前没有可用牌」，而引擎的 `canBeat` 明明允许。

本项目已因这一类缺陷反复出 bug：

- 2026-10-26 连段枚举按「该点数的所有牌塞进同一段」→ 混合张数组合被判 INVALID，真正的 `[9,10,J]` 从没被枚举过
- 2026-10-27 改成「每点各取一张」→ **双龙/连珠蛋再也枚举不到**
- 2026-11-02 k 上界只到 3 → **假八 / 三连假八从没被枚举过**
- 2026-11-03 枚举层无「低端 A」形态 → **A23 枚举不出**；`MAX_SEQ=12` → **13 张最长龙（2..A）枚举不出**

## 2. 何时用

- 改了 `skills/da-a-game-rules/SKILL.md` 的**牌型表、压制关系、张数上限**之后
- 改了 `src/hand-types.js`（识别层）或 `src/combos.js`（枚举层）之后
- 玩家报「提示说没有可用牌」但引擎逻辑看着没问题时
- 交接前做一次全量体检

## 3. 怎么查

### 3.1 跑机械对账脚本（只读）

```bash
cd AGame/da-a-game
node skills/audit-rules-vs-impl/scripts/audit.js
```

脚本做四件事，**全部只读，不修改任何文件**：

1. **枚举可达性** —— 对 SKILL §6 牌型表里的每种牌型，用**最小可构成手牌**去问 `candidateCombos`：枚举层出不出得来。
2. **跨型矩阵** —— 对 §6.3 全局链上**每一对**牌型，两个方向都跑 `canBeat`，与 §6.3/§6.4 的应有结论比对。
3. **识别 ↔ 枚举一致** —— 枚举出来的每个组合，识别层判定不得为 INVALID。
4. **排列对称性** —— 同一组点数的**不同排列**（`445`/`454`/`544`），识别层结论必须一致。

脚本输出的是**排查清单，不是判决**：命中为 0 只说明"没有明显线索"，最终判定要人读断言。

### 3.2 人读的部分（脚本查不出来的）

- **§6.3 POWER 表有没有被压平**：链上**每两个相邻词条必须不同值**。`蛋子 / 龙 / 对子 / 单张` 是**四级严格分层**，给同一个值就是 bug（症状：凡是蛋子或大蛋子当攻方的格子全 false）。唯一例外是**双龙**——§6.3 单独给它写了规则，不参与线性链，单列且不与链上任何档撞值。
- **§6.4 特殊规则是否被绕过**：单大A 只管单张；单王只管单张；双王/三王/四王各有显式可管列表；双龙只被双龙或大蛋子及以上压。跨型压制**走 POWER 表，不走 `compareHands`**。
- **两套 rank 编码是否分流**：**只有 SINGLE 允许大A 加成**；PAIR/TRIPLE/BIG_TRIPLE/TRUE_SEVEN/TRUE_EIGHT 一律不含大A 加成。整副对子被大A 抬起来是典型 bug。
- **枚举层的长度上限是否覆盖了识别层能认的最大长度**：识别层认 13 张 2..A，枚举层上限却是 12 → 枚举不出。

## 4. 判定规则

| 现象 | 判定 | 动作 |
|---|---|---|
| 识别层认、枚举层不出 | **枚举层缺陷** | 改 `src/combos.js` |
| 枚举得出、识别层判 INVALID | 枚举层生成了非法组合 | 改 `src/combos.js` |
| 两层都不认，但规则要求认 | **识别层缺陷** | 改 `src/hand-types.js` |
| 两层都认，但跨型压制方向错 | **POWER 表缺陷** | 改 `src/hand-types.js` |
| 规则文本本身自相矛盾 | **规则缺陷** | 交用户裁定，**不要自己选一边实现** |

最后一行最重要：规则冲突时**停下来问**，不要挑一个"看起来对"的读法写进代码。

## 6. 变异测试（修枚举层/识别层时必做）

退回旧实现 → 断言必须**精确失败**（不是全挂）→ 再恢复。
**变异期间不要并行跑回归**——临时回退的源码会被并行进程读到，报出看似真实的失败。
